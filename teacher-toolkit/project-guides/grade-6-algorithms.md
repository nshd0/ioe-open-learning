# Lesson Guide — Algorithms (Grade 6)

## Overview
This lesson teaches students to design, test, and improve simple algorithms through a hands-on sorting task. It emphasises clarity, testing, and iterative improvement.

### Learning objectives
- Write a clear, ordered set of instructions (algorithm) for a simple task.
- Test the algorithm by having peers follow it and record where it fails.
- Improve instructions based on observed problems.

### Time
40–50 minutes (can be split across two sessions for slower groups)

### Materials
- 12 small objects per group (buttons, stones, bottle caps) varying by colour and size
- Paper and pens for each group
- Counters or grid paper (optional)
- Printed student activity sheet: `grades/grade-6/lessons/06-algorithms-print.html` (print 1 per student or per group)

### Class size and grouping
Groups of 3 work well (Writer, Runner, Observer). Rotate roles so each student practices writing and following algorithms.

### Lesson flow
1. Intro (5 minutes): Explain the goal and show a short example of an ambiguous vs precise instruction.
2. Activity (25–30 minutes): Groups follow the student sheet: write algorithm, run, observe, swap roles.
3. Review (10–15 minutes): Share examples of unclear steps and discuss improvements.

### Teacher facilitation notes
- Encourage precise language: use exact terms (e.g., "pick the largest red object" vs "pick a red one").
- If Runners ask clarifying questions, record them—this shows where the algorithm lacks detail.
- Provide sentence stems: "First, ...", "Then, ...", "If ... do ..." for students who struggle.

### Differentiation
- Support: Provide templates with numbered step headings and example verbs for emerging learners.
- Challenge: Ask advanced students to write an algorithm that works for any number of objects using loops (e.g., repeat until no unsorted objects remain).

### Assessment rubric (Emerging / Developing / Secure)
- Writes ordered steps with some missing details / Steps are complete but sometimes ambiguous / Steps are precise and produce correct result when followed
- Requires multiple clarifications / Requires minor clarifications / No clarifications needed
- Reflection shows little insight / Reflection identifies at least one fix / Reflection proposes clear improvement and test

### Safety and accessibility
- Use non-sharp, non-toxic objects. Be mindful of students with sensory sensitivities—offer visual or tactile alternatives.
- Pair students to balance strengths and ensure inclusive participation.

### Low-tech alternatives
- Use paper cards with object descriptions instead of physical objects.
- Role-play algorithms with students acting as "objects" following instructions.

### Extensions
- Translate the algorithm into a simple flowchart.
- Compare two algorithms and time which is faster for larger piles.
